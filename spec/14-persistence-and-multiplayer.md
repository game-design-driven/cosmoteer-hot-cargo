## 14. Persistence and multiplayer

57. Heat, the stages that already started, the sector index, the run result, notoriety and the peak tier (requirement 19), the event state (requirement 76), the chain state (requirement 172), the contract state (requirement 107), the shared choice votes and mode (requirement 607), the diplomacy state (requirement 586), the multiselect drafts (requirement 592), the enemy scaling setting (requirement 330) and the run log (requirement 730) are saved with the career save and loaded with it. Ship tactics are saved with each ship, not in the run state (requirement 407). Resolved: the save hook is a postfix on `CareerGameModeManager.WriteTo` (path `HotCargo`), and the load hook a postfix on its `GenericSerialReader` constructor. A save from before the mod was enabled has no Hot Cargo state. At load, a new run starts at that point of the career, with the starting Tech Vault and the run intro.
58. All logic that changes simulation state runs in the deterministic simulation tick. It uses the simulation random source, not `System.Random`. The integrity hash includes heat, sector, stages, result, fleet tech, delivered units, run time, the loss timer, the event serials, notoriety, the peak tier, the contract counts, the shared choice votes and mode and the tunables hash, so a divergence starts a resync at once. Each ship's hash includes its tactics state (requirement 411). Each desync that the game detects writes an `MP DESYNC` line to the Hot Cargo log.
59. The fleet tech count and the loss rule count all human players together, and tech in derelict ships (requirement 449). A loss ends the run for everyone.
60. In multiplayer, only the host's game watches its tunables file (requirement 850). A new co-op run starts with the default tunables on every machine. On its first frame the host sends its `tunables.rules` as a multiplayer input (`HotCargoTunables`), and every machine applies it at the same tick. The starting vault and the first system's offers exist before that and use the defaults. A loaded game uses the tunables in the save until the host's file changes. The client's file has no effect. Changes in the host's settings menu (requirement 504) and changes of the host's file (requirement 850) use the same input. The heat panel shows a short hash of the tunables in effect, so players can compare.
61. Debug keys do not work in multiplayer.
1510. **Money from parallel updates.** Vanilla adds money from the parallel ship update: `ResourceManager.FixedUpdate` runs on worker threads and refunds expired pre-purchases with `PlayerState.AddMoney`. Each add is atomic (one lock), so two ships that refund one player in the same tick give the same total on every machine. Playtest 2026-11-15: a player repaired a ship with resources bought by the other player, the ship jumped to a station, two refunds of 50 met in one tick, the host lost one and the game desynced. The co-op step `hunters.capture` checks it (`moneyrace`).
1512. **Sim positions only.** Sim logic reads a ship's position from `Ship.DetWorldCenter` or its stasis spawner, never from `Ship.Location` or `ObjectiveTargetShip.Location`: those read the scene node position that rendering moves, so it differs between machines. Mission objectives use `SimQueries.DetLocation` (escort, shady trap, tow, hand-over, hold-out, lair). Playtest 2026-11-15: after a resync, the convoy freighter reached the ambush point (requirement 36) at a different tick on each machine, and the raiders spawned at different spots. The co-op step `missions.escort-ambush` checks it.
1513. **Same start world.** At the start of each co-op game every machine logs one hash per part of the world it built (`MPWORLD`: seeds, sim random, ships, crew, nuggets, nebulas, doodads, sim mode, missions, stasis, offers, run state) and the content of the offers and stasis tags (`MPWORLDLIST`). `scripts/coop-report.sh` pairs the lines of host and client by game and fails with "start world differs" and the parts. The game's own check sees a different start world only as a desync at the first ticks. Every world generation roll of the mod uses shared seeds: the system seed (`MapNodeData.RandomSeed`: vanilla generation, the stash offer), the career seed (`Run.SectorRand`: chains), the host's career settings (enemy scaling) and default tunables (spawn chances; no run is active while the first system generates). #184: one CI co-op run desynced at tick 1 of a new game; 80 start worlds on the PC matched.
