## 36. Telemetry

Logs and telemetry of game sessions, for analysis of test runs and playtests. TELEMETRY.md holds the schema and the tools. Code: `src/HotCargo/Telemetry/`. Numbers: the `Telemetry` tunables section.

530. Each game session writes one JSONL file `<run id>__<session id>.jsonl` in the `telemetry` folder of the mod. A session is one game from its start or load until it closes. `scripts/deploy.sh` keeps the folder.
531. A run has an ID that the career save keeps (path `HotCargoTelemetry`), so a loaded game continues it. A new career gets a new ID. The first line (`session.start`) holds the run and session IDs, the game version, the mod version with its git commit, the tunables hash, a hash and a full copy of the tunables in effect, the galaxy seed, the map size, the difficulty settings, the player count and the autotest label.
532. Every event has the event name, real time, game time of the run, sim time of the session, sector index, system, tier, sector type, heat and fleet tech count.
533. **Run**: new run, load, save, jump (with the stay), system entry (with the previous stay and its missions), win, loss with the reason, and the session end with its reason.
534. **Heat**: every heat change with its source and caller, time and trail heat summed over `AccrualSeconds`, stage starts and strike waves. **Tech**: count changes with a cause, tech value steps and vault hits. Notoriety is in the tech value events and the snapshots.
535. **Economy**: money and fame changes with their source and caller, reputation changes, and station trades with the unit price. A blueprint unlock shows as source `tech_unlock` (requirement 1586); any other money change outside `PlayerState.AddMoney` shows as source `untracked`.
536. **Missions**: offers with their contract terms, accepts, and the end with the result (spec 166 names), the time to finish and the sell-out flag. **Story**: event pages, choices with the rolled outcome, results with their effect lines, and chain starts and stages.
537. **Combat**: a census at the first visit of a system, every later non-player ship spawn, derelict ships by side, ships that leave the system, human crew deaths, and damage summed by the side of the damaged ship. **AI**: the strategy module that drives each AI ship, with a switch event at most every `AiSwitchMinSeconds` per ship and `AiEventsPerMinute` in total, and sums of every module, tactic and focus fire decision in the snapshots.
538. **Snapshots**: every `SnapshotSeconds` game seconds, at each jump and at the run result: the run state, money, fame, contracts, and the value, firepower, parts, vaults and crew of each player ship.
539. **Performance**: every `PerfSeconds` real seconds: frame time (mean, percentiles, maximum, slow frames), sim tick time, GC counts and pause time, memory, and the time and share that telemetry used. **Co-op**: player count changes, desyncs and co-op game loads (joins and resyncs).
540. Each category has a switch in the `Telemetry` tunables section, and `Enabled` turns all telemetry off. The section is validated with the other tunables (spec 53).
541. Telemetry never blocks a frame or a sim tick: game threads add a line to a list, and a background thread writes it once per second. A file that reaches `MaxFileMegabytes` continues in a part file. At session start the oldest files go until the folder is below `MaxFolderMegabytes`. More than 200,000 lines that wait are dropped and counted.
542. Telemetry measures its own time on game threads and reports it. Target: well below 1 % of the real time of a session, which is the share of frame time at a steady frame rate. The autotests check it.
543. Telemetry reads game state only. It never changes the simulation and uses no sim random source, so each co-op machine writes its own file, with its own switches, without a desync.
544. `scripts/pull-telemetry.sh [SLOT...]` copies the files of the main slot and the test slots to `../.telemetry/`. `tools/telemetry` (`uv run hc-telemetry`) writes a markdown and a self-contained HTML report: per sector time and missions, heat curve and sources, money and power over time by tier, tech sales, losses, hunter outcomes, AI module frequencies and performance. `scripts/autotest-all.sh --telemetry` pulls and reports after a test pass.
545. Every autotest makes telemetry with the script name as its label. `telemetry-basic` checks the categories, a save and load and the overhead; `telemetry-run` is a scripted run over three systems that ends with a win and checks that each event kind shows. It shields the player's ships (test command `shieldplayers`), so it does not depend on survival.

Playtest 2026-11-14 (run `r20261114-212053-eb3e`) showed gaps: wreck pieces counted as ships, captures and ships left behind did not show, and some numbers were wrong. Requirements 1580 to 1591 close them. Pure rules: `Telemetry/TelemetryModel.cs`.

1580. **One ship, one side, one wreck.** Vanilla turns each piece of a broken ship into its own ship and junks each one (`SimModeManager.OnShipSplit`). A split adds its pieces to the lineage of the ship. `combat.destroyed` fires once per lineage, when its last live piece becomes a wreck, with the name, side, value and tags of the ship before it broke. Every event names a piece by the side of its ship, so a hunter stays a hunter in damage, AI, spawn and wreck events.
1581. **Fleet changes.** `combat.captured`: a ship that becomes a player ship, with its side before it was a wreck or another side's ship, how (`claim`, `joined`, `other`), its value, hyperdrive and tech. `combat.fleet_left`: a player ship that stays behind at a jump, is gone after a co-op resync or join (compared with the previous session in the same process, in the same system), or becomes another side's ship without a wreck.
1582. **Jump ships.** `run.jump` lists the ships that jump (in jump limbo) and the human ships that stay in the old system. Each has its hyperdrive, hyperium, drive capacity, the vanilla fuel cost of the jump path (`FtlManager.GetTotalFtlMapJumpFuelCost`), too big (cost above capacity), tech and parts.
1583. **Diplomacy.** `dip.hail` (vanilla `AIHailPlayer`: offer or demand of surrender, with the price), `dip.surrender` (vanilla `MPShipSurrenderedInput`: who gives up, the price, accepted), and `dip.deal` (each Hot Cargo hail choice through `Deals.Decided`: offer, amount, price, chance, roll, accepted). Each has the odds, confidence, bravery, stance and allies of the risk model (requirements 1520 to 1524). Switch `Telemetry.Diplomacy`.
1584. **Session number.** `session_no` is the larger of the count in the save and the session files of the run on this machine, plus one, so a load of an older save gets a new number.
1585. **Privacy.** Log lines in telemetry files have no user folder name (after `\Users\`, `/Users/`, `/home/`) and no Steam ID (17 digits that start with 7656119): they become `<user>` and `<steam id>`. The session start log line names only the file.
1586. **Blueprint money.** Vanilla charges a blueprint unlock with a direct set of the money (`CommTechsTab.MPBuyTechInput`). Telemetry logs it as `econ.money` with source `tech_unlock` and the tech ID.
1587. **Vault deconstruction.** Crew that take a vault apart are no vault destruction: `tech.vault_hit` has cause `vault_deconstructed` and `destroyed` false, the tech hint is `vault_deconstructed`, and the lost health is no damage in `combat.damage`. Each `tech.vault_hit` names the ship and its player, read before vanilla takes the part off the ship.
1588. **Fights.** `combat.fight` joins damage windows with damage to the players, hunters or hostiles, and wrecks of those sides, until `Telemetry.FightGapSeconds` (90) of game time pass without either, the sector changes, the players jump or the session ends: start, end, sides, damage and wrecks by side, kills, player ship losses and crew deaths. A fight without such damage is dropped.
1589. **Mission time.** `mission.ended` has `duration_s` in run game seconds since the accept. The telemetry save data keeps the accept times, so a load keeps them.
1590. **Loss timer.** `tech.loss_timer` fires when the state changes: `idle`, `running`, or `paused` with the reason (`local_jump`, `jump_limbo`, `ships_elsewhere` with the waiting ships by system) from the same check as the timer (requirement 12, `LossTimer.PauseReason`).
1591. **Real time split.** `perf` and `session.end` split the real time of frames into paused, build mode (not paused) and play, from this machine's view.
