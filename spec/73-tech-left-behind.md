## 73. Tech left behind

Tech that stays in a system when the players move to another system is lost. Code: `src/HotCargo/Tech/LeftBehind.cs`, the warnings in `Ux/JumpWarnings.cs`, the pure rule in `Ux/JumpWarningsModel.cs`. Requirements 2520 to 2529. Issue #351: players left a ship with their tech in another system and worked elsewhere with no tech aboard. Heat grew at the no-tech rate, and the waiting ships paused the loss timer. That broke the pillar of requirement 2203 ("no wait and it ends"). User decision 2026-11-26: "If you leave tech behind when moving to new system it should disappear ie you lose it."

2520. **Rule.** When the players move to another system, all of their tech in the old system that does not come along is lost: the vaults, normal storage and waiting tech (requirement 1554) of the human ships that stay, derelicts (requirement 449), tech in crew hands outside the ships that jump, tech crates, tech that friendly ships hold (requirement 575), and tech that hunters hold (requirement 446). A move is a jump (`GameRoot.DoHumanPlayersFtlJump`), the vanilla map switch to a system with own ships (`MPJumpToNodeInput`), and the recall (requirement 1601). So ships that wait in another system never hold tech, and the loss timer does not pause for them (requirement 12).
2521. **Moment.** The rule runs in `CareerGameModeManager.OnSwitchingSimulation` (the hook `Run.Hooks.SystemLeaving`). Every machine runs it there after the synchronized jump signals (`MPSignals.JumpingSwitchSim`). The ships that jump are in the new sim at that point, out of jump limbo, so the old sim holds only what stays. Vanilla archives the old sim before this point (`GameRoot.JumpToNode`, `GameSimArchive.SaveSim`). So the code removes the tech from the old sim and archives that sim again, and a return finds no tech there.
2522. **Before the move.** The players see the tech that a move leaves behind before they confirm it:
    - The jump dialog on ENGAGE (requirement 1565) starts with "N tech will be left behind and lost.", or "All your tech stays behind: N tech will be lost." when no tech comes along. It shows also when every local ship is ready. The ships that come along are the significant human ships that are ready to jump, like the vanilla jump.
    - A map click on a system with own ships, and the "Go to <system>" button (requirement 1601), ask first with the same line and "Go to <system> anyway?". Without tech in this system, the switch goes at once, like vanilla.
    - The stranded line (requirement 1567) adds "N tech here is lost when you go." The automatic recall does not ask: the line counts down in front of the players.
    `JumpWarningsModel.LeftKind` picks the line: none, some or all. `Ux.JumpWarnings` off turns these warnings off with the rest of section 58.
2523. **After the move.** A toast, a chat line and a run log line (kind Loss) say "N tech left behind in <system> is lost." Telemetry adds the tech hint `left_behind`.
2524. **Friendly holders.** Tech that a friendly ship holds in the old system is lost too. Interpretation of the user decision: the holder cannot follow, and one rule covers every place.
2525. **Co-op.** The rule reads and changes sim state and run state only, in a stable order (ships by ID, crew by ID, crates in nugget order), at the same point of the switch on every machine. The co-op step `tech.left-behind` (session `coop-economy`) checks that both machines remove the same tech.
2526. **Tests.** Unit tests `JumpWarningsModelTests` (the line kind). Game test `tech-left-behind`: the ENGAGE count with crates, a jump that leaves the carrier, the loss timer that runs, the switch dialog with "no" and "yes", and no tech on the return. `ux-stranded-recall`: the recall finds no tech.
