## 73. Tech left behind

Tech that stays in a system when the players move to another system is lost. Code: `src/HotCargo/Tech/LeftBehind.cs`, the warnings in `Ux/JumpWarnings.cs`, the pure rule in `Ux/JumpWarningsModel.cs`. Requirements 2520 to 2529. Issue #351: players left a ship with their tech in another system and worked elsewhere with no tech aboard. Heat grew at the no-tech rate, and the waiting ships paused the loss timer. That broke the pillar of requirement 2203 ("no wait and it ends"). User decision 2026-11-26: "If you leave tech behind when moving to new system it should disappear ie you lose it." User decision 2026-11-27: "If tech is left behind we should first want to try and prevent and if it still happens u lose right away" (requirement 2527).

2520. **Rule.** When the players move to another system, all of their tech in the old system that does not come along is lost: the vaults, normal storage and waiting tech (requirement 1554) of the human ships that stay, derelicts (requirement 449), tech in crew hands outside the ships that jump, tech crates (also crates in stasis, `SimStasisManager.StasisNugget`: vanilla takes crates far from every player out of the sim), tech that friendly ships hold (requirement 575), and tech that hunters hold (requirement 446). A move is a jump (`GameRoot.DoHumanPlayersFtlJump`), the vanilla map switch to a system with own ships (`MPJumpToNodeInput`), and the recall (requirement 1601). So ships that wait in another system never hold tech, and the loss timer does not pause for them (requirement 12).
2521. **Moment.** The rule runs in `CareerGameModeManager.OnSwitchingSimulation` (the hook `Run.Hooks.SystemLeaving`). Every machine runs it there after the synchronized jump signals (`MPSignals.JumpingSwitchSim`). The ships that jump are in the new sim at that point, out of jump limbo, so the old sim holds only what stays. Vanilla archives the old sim before this point (`GameRoot.JumpToNode`, `GameSimArchive.SaveSim`). So the code removes the tech from the old sim and archives that sim again, and a return finds no tech there.
2522. **Before the move.** The players see the tech that a move leaves behind before they confirm it:
    - The jump dialog on ENGAGE (requirement 1565) starts with "N tech will be left behind and lost." when some tech comes along. It shows also when every local ship is ready. The ships that come along are the significant human ships that are ready to jump, like the vanilla jump. The relay jumps of the run map (section 74) are ENGAGE jumps.
    - A map click on a system with own ships, and the "Go to <system>" button (requirement 1601), ask first when tech stays in this system. No ship comes along on such a switch, so that tech is all the tech: the question of requirement 2527. Without tech in this system, the switch goes at once, like vanilla.
    - When no tech comes along, requirement 2527 applies.
    `JumpWarningsModel.LeftKind` picks the case: none, some or all. `Ux.JumpWarnings` off turns these warnings off with the rest of section 58.
2523. **After the move.** A toast, a chat line and a run log line (kind Loss) say "N tech left behind in <system> is lost." Telemetry adds the tech hint `left_behind`.
2524. **Friendly holders.** Tech that a friendly ship holds in the old system is lost too. Interpretation of the user decision: the holder cannot follow, and one rule covers every place.
2525. **Co-op.** The rule reads and changes sim state and run state only, in a stable order (ships by ID, crew by ID, crates in nugget order, crates in stasis by ID), at the same point of the switch on every machine. The co-op step `tech.left-behind` (session `coop-economy`) checks that both machines remove the same tech.
2526. **Tests.** Unit tests `JumpWarningsModelTests` (the case: none, some or all). Game test `tech-left-behind`: the ENGAGE question with "Lose the run", the count with crates, a jump that leaves only crates (the run goes on), the switch question with "Cancel" and "Lose the run", and the loss on arrival. `ux-jump-warnings`: "Lose the run" on the real ENGAGE click. `ux-stranded-recall`: the stranded line and the loss after the automatic recall, with the carrier's tech in crates in stasis. Co-op step `tech.left-all` (session `coop-economy`): both machines lose the run at the same switch. Screenshots: `docs/screenshots/jump-carrier.jpg` (script `tests/screens/jump-carrier.txt`), `docs/screenshots/tech-left-switch.jpg` (script `tests/screens/tech-left-switch.txt`).
2527. **All tech left behind.** First the game tries to stop it; if the players still go, the run is lost at once.
    - A move after which no tech comes along (requirement 2522: the case "all") asks first, on ENGAGE, a map switch and the "Go to <system>" button. The question starts with its own large red line "All your tech stays behind. You lose the run.", and its first button says "Lose the run" instead of "Okay".
    - When a switch left tech behind (requirement 2520) and the fleet tech count of the new system is 0 on arrival, the run is lost at once (`Run.Lose`, reason "All the tech stayed behind in <system>."), without the loss timer of requirement 443. The check runs in `Run.Hooks.SystemEntered` of the same switch, on every machine.
    - Some tech left behind keeps the rule of requirement 2520: that tech is lost, and the run goes on. Tech lost in other ways (a destroyed vault, a sale, a crew death) keeps the loss timer.
    - The automatic recall (requirement 1601) does not ask. While tech stays in this system and no own ship is here, no move can take it along, so the stranded line shows the same red line during the countdown.
    - Limit: in co-op only the player who clicks a map switch sees the question; the other players vote in the vanilla vote window. Revisit if co-op players switch by accident.
