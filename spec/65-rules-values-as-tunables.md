## 65. Rules values as tunables

The settings menu changes every tunable mid-game (section 29). Some designer numbers lived in rules files, so the menu could not reach them. These are tunables now. The C# code writes them into the loaded game rules (`GameApp.Rules`), which every game of the process shares. Code: `Balance/FuelRules.cs`, `Journey/MapRules.cs`, pure rules in `Journey/MapRulesModel.cs`.

2411. **Fuel.** `Balance.FuelPrice` (the hyperium buy price), `Balance.MapJumpFuelCostPerMassDistance` and `Balance.LocalJumpFuelCostPerMassDistance` (the jump costs of the ship classes that a career allows) and the station fuel stock (`StationFuelTypedMin`/`Max`, `StationFuelUntypedMin`/`Max`, the hyperium row of every sector type) replace `mod/balance/actions.rules`. They go into the rules before a new galaxy is made (the first system generates before the run starts, with `TunablesFile.ForNewGame`: this machine's file in single player, the defaults in co-op), at every game start and load (`Run.Hooks.GameStarted`), and at every tunables change. The price and the jump costs apply to the next trade and jump; the stock applies to stations of the next new system.
2412. **Fuel stack.** `Balance.FuelStackSize` goes into the rules only before a new galaxy and at a game start or load, not at a tunables change: storage tiles that hold more fuel than a smaller stack would break. The menu tags it "next new or loaded game".
2410. **Steel and coil stack.** `Balance.BuildStackSize` (80; vanilla 40) is the stack of each resource in `Balance.BuildStackResources` (steel, coil): units per storage tile and per factory buffer tile. It goes into the rules at the same points as the fuel stack (requirement 2412). The stack picture steps by stack ÷ pictures (`ResourcesPerStackSprite`: 2 for 40 pictures), so a full tile shows the full picture. A crate in space and a crew trip still hold `MaxPerNugget` (10). Coil2 and tristeel keep 40. Reason: players built after every fight to store loot that did not fit (`docs/loot-volume-study.md`).
2413. **Co-op and the rules hash.** Every machine writes the same values at the same point: the defaults or the save at the start, the host's input later (requirement 504). The multiplayer rules hash (`Rules.RulesHash`, which the game list and the join check compare) is computed from the rules files before the first write, so these values never block a join.
2414. **Galaxy.** `Journey.RunSectorCount` (2 to 20), `Journey.FinalSectorTier` (2 to 16) and `Worlds.SystemTypeWeights` (a weight for each sector type of `mod/worlds/archetypes.rules`; a type that the list leaves out does not appear) go into the spawners of the run map (section 73) just before a new galaxy is made, so they apply to new runs. Each co-op machine makes the galaxy itself before the host's file arrives, so co-op uses the defaults. Tests: unit tests `MapRulesModelTests`; `balance-rules` changes the fuel price and the stack through the menu; `journey-run` makes a second galaxy from a tunables file.
