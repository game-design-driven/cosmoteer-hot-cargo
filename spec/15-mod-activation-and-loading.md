## 15. Mod activation and loading

62. The C# code loads through a .NET startup hook. `scripts/deploy.sh` adds `STARTUP_HOOKS` to `Cosmoteer.runtimeconfig.json` and writes `Bin/steam_appid.txt`. It adds the hook to a copy of the game's own file, and a file without the hook (after a game update) becomes the new copy. On macOS, `release/install-mac.sh` adds the hook to the game folder of Cosmoteer for macOS, and that app runs the hooks of the game's `Cosmoteer.runtimeconfig.json`.
63. The C# code does nothing unless the Hot Cargo rules mod is enabled in the game's mod list. With the mod off, the game stays vanilla, including vanilla multiplayer.
64. A Steam "verify files" removes the hook. Run `scripts/deploy.sh` again to restore it.
2260. **Installs keep the player's files.** The player installers (`release/install-mac.sh`, `release/install.ps1`) and the PC install into the player's slot (`scripts/install-player.sh` through `scripts/slot-install.ps1`) copy the release files over the mod folder and delete nothing. So the files that the mod writes under its folder stay: `telemetry/` (session files, `notes.jsonl`, note screenshots, `players/<name>/`), `screenshots/`, `testships/`, `vault-report.txt`, `tune.request`/`tune.result` and the log in `csharp/`. The release's `tunables.rules` is a template and goes in only when the player has none. A file that an older release shipped and a newer one does not stays behind; nothing loads it, because `mod.rules` names every rules file and the loader loads only `csharp/HotCargo.dll`. A test slot is still replaced but for its telemetry, so one test leaves nothing for the next. The uninstallers (`release/uninstall.ps1` with `uninstall.bat`, `release/uninstall-mac.sh`) use the same list: they delete each file of the release's `hot_cargo` folder but `tunables.rules`, then the folders that are empty after it, so the player's files stay too. They restore `Cosmoteer.runtimeconfig.json` and remove the loader; the Mac one also takes Hot Cargo out of `EnabledMods`. Test: `scripts/test-install-keep.sh` installs and uninstalls (CI runs the Windows pair with pwsh; on a Mac it runs the Mac pair too). Playtest 2026-11-23: a reinstall deleted the telemetry of a whole two-Mac co-op playtest.
2261. **A boot failure never stops the game.** `Mod.Boot` applies the Harmony patches one area at a time; an area is the namespace of its `Register` method in `Mod.Areas`. The base (`Core`, `Ui`, `Dev`, spec 17) patches first: when it fails, every patch goes, Hot Cargo stays off and the game starts as vanilla. Then each area patches and registers in its start order. When an area's patch or `Register` throws, its patches go (also the ones of a half-patched class), the area is off for this game process (`Mod.AreasOff`), the overlay and the log report it, and the other areas start. Reason: a game update that removes a patch target made the game unable to start. Limit: an area whose `Register` throws half-way keeps the hooks that it added before the throw.
