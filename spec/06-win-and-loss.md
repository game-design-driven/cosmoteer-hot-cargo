## 6. Win and loss

6. **Win**: the players sell at least one tech unit to the Buyer. The run is won when the crew deliver the first units of the sale.
7. When the players win, a win panel shows the score. Score = money + units still held × the Buyer unit price − the debt rule of requirement 1411. The Buyer unit price = tech value × `BuyerPriceFactor` (default 4) × the run's Buyer price multiplier (requirement 84; 1 unless the players took an advance). A sale to the Buyer pays that price for each unit, so delivered units are in the money once, and an unsold unit counts as much as a sold one. The players go to the Buyer instead of a station because of this factor. Delivered units are the units of all crew deliveries to the Buyer; a delivery after the win sets the score again. The run state saves the score and the delivered units. `Journey/ScoreModel.cs` holds the formula as a breakdown; the Debt area adds its step (requirement 2590).
8. After a win, heat turns off. The win panel shows the score and the run numbers, and the players can continue the career.
9. **Loss**: when the fleet tech count reaches 0, the loss timer starts (requirement 443). When it runs out, the run is lost. Any cause counts: vault damage, a destroyed vault, crew that die while they carry tech, or a sale of the last unit. A Buyer delivery is the only exception, because it wins the run first. A move to another system that leaves all tech behind loses the run at once, without the timer (requirement 2527).
10. A loss shows the game-over screen with the title "The corporation recovered the tech", the reason and the run numbers.
11. Outside Ironman, the mod does not delete save files after a loss. In an Ironman career a loss deletes the save (requirement 685).
12. The loss check runs only when the count is certain: no ship jump is in progress (no ship in jump limbo; the local jump animation does not count, because it differs between multiplayer machines), The count must stay at 0 for `LossGraceSeconds` (default 180 s, the loss timer of requirement 443). An uncertain count pauses the timer; it does not reset it. Ships that wait in another system do not pause it: a move to another system loses the tech that stays behind (requirement 2520), so they hold none. When no human ship is left in the current system, the timer runs, and a recall takes the players to the waiting fleet (requirements 1566, 1567, 1601). The run state saves the timer, so a load or a client that joins sees the same timer.
